The draft starts the exact pinned test executable directly and owns its PID. It drains stdout and stderr with separate listeners and separate raw files, keeps distinct timestamped line logs, and waits for both stream drains before closing sinks. It samples only /proc/<owned-pid>/status VmLck and VmRSS plus the Max locked memory line from /proc/<owned-pid>/limits immediately and every five seconds, stopping at 740 rows.
Only a complete individual libtest result line matching `test <name> ... FAILED` (optionally surrounded by whitespace) triggers the early stop. Panic text, expected caught panics, and arbitrary text containing FAILED do not trigger. On a match it snapshots resource fields and the last 300 timestamped lines to failure-trigger.json, sends SIGTERM only to the owned test PID, waits up to 30 seconds, then SIGKILLs only that PID if still live. It drains both streams, marks the invocation interrupted/incomplete, and never calls it a suite pass. Without a failure line it records natural exit or the fixed 3600-second timeout plus grace honestly.
