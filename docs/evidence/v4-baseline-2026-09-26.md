## Migration follow-up

Dispatch archive 2/3 to `revault_archive_v3_reader`, Vault structure 3/container 3
to `revault_vault_v3_reader`, and keep versions 1/2 on their existing exporters.
Unknown structure/container tuples now fail explicitly instead of attempting a
current reader. Original native fixtures remain byte-for-byte unchanged.

The old expected archive Start records omit owner identity. Their generators use
random signing keys that were not retained. The current import requires the
established owner's key when the exporter provides its fingerprint. Do not fix
this by stripping owner_fingerprint, supplying a newly generated owner, rewriting
historical native bytes or disabling the strict migration check.

Required follow-up: retain a separate historical fixture with synthetic known
owner credentials using its frozen writer, verify owner-preserving migration and
explicit rejection with a wrong key; keep existing unsigned/unknown-owner cases
with honest capability expectations. Review schema-extension handling in old
logical snapshots without removing comparisons of their existing fields. Add
v4/current Vault-container fixtures only against the selected format, with an
explicit policy for existing experimental artifacts.

## Deterministic mirror preparation regression

The new `changed_source_after_preparation_rolls_back_appended_and_reused_payload`
test uses public CLI commands to initialize the Vault, create an archive/mirror,
populate/delete files and verify persisted content. An explicit `e2e-test-hooks`
feature pauses at final source verification using a bounded file rendezvous.
Normal builds contain no pause hook. This makes the changed-source refusal
deterministic without relying on filesystem timing races.

The test uses signed plaintext/raw archives to directly observe prepared bytes.
Read-only physical inspection is the documented exception because no CLI command
exposes uncommitted payload. It proves append versus reuse by the payload offset,
then changes the host file and resumes. After refusal it stops the agent, reads
the surviving neighbour through a fresh CLI process, checks the new path is absent,
checks original length and absence of the abandoned marker, and runs public
`doctor --deep` to verify accounting and zero reusable space. A later legitimate
update succeeds and its stored bytes are independently read back.

```sh
cargo test -p revault_cli --test mirror_cli
cargo test -p revault_cli --features e2e-test-hooks --test mirror_cli changed_source_after_preparation
cargo test -p revault_cli --features e2e-test-hooks,revault_lockbox_api/native-block-layout --test mirror_cli changed_source_after_preparation
cargo test -p revault_migration --test retained_fixtures historical_fixtures_export_with_frozen_readers -- --exact
```
