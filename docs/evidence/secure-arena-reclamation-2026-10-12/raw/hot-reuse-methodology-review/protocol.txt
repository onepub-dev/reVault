SecureVec hot-reuse protocol draft — REVIEW ONLY

No hot process is launched from this draft. Existing pinned binaries are pressure-only: the exact preserved Rust source `raw/isolated-pressure-profile/securevec_pressure_profile.rs.txt` has no hot subcommand, so the binaries cannot perform this protocol. Draft execution is gated off until a reviewed hot-capable source/binary epoch is authorized, built, and pinned; this task performs no build.

Scope: 56 fresh processes, 2 sizes × 14 rounds × 2 variants. For each process, run one prewarm allocate / verify / drop outside the inner timer, then 64-byte capacity × 100,000 iterations or 65,536-byte capacity × 10,000 iterations. Every iteration allocates one SecureVec, verifies exact synthetic bytes through scoped access, and drops it. No output or /proc sampling occurs inside the timed loop. Weak-allocation policy remains false and soft/hard RLIMIT_MEMLOCK remain exactly 8 MiB. Run under taskset CPU affinity 0-4. Alternate old/new order every round, with both variants run for each size in every round. Per-process timeout is 120 seconds; whole batch deadline is 15 minutes; stop on any failure and never retry.

Admission for each process requires exit 0 and exactly one JSON record with exact requested kind, variant, size, iteration count, `byte_verification_ok=true`, `weak_policy=false`, `memlock_soft_bytes=8388608`, `memlock_hard_bytes=8388608`, finite positive `inner_elapsed_ns`, and `baseline_VmLck_bytes == 0` and `prewarm_live_VmLck_bytes == before_inner_VmLck_bytes == after_inner_VmLck_bytes > 0`, all <=8388608; fresh-process baseline VmLck must be 0. This proves the backed arena remained locked and showed no retained VmLck growth during reuse. Record Dart Stopwatch whole-process elapsed microseconds and report separately from inner operation time. GNU `time` is not used because its 0.01-second granularity is too coarse for these short processes. Preserve stdout/stderr independently per process, label every sample `hot-reuse-fixed-56-v1`, and append an admitted JSONL row only after validation.

Before and after the batch, hash and compare both executables, the exact hot-probe source, each isolated Cargo.lock, copied crate manifests, and all copied Rust source files. The run is inadmissible if any identity changes. Exclude rounds indexed 0 and 1. Pair measured adjacent rounds (2,3), (4,5), ... (12,13), giving six paired blocks per size. For each block and metric, calculate the geometric mean of new/old ratios across its two constituent rounds. Analyze four endpoints: each of two sizes × inner per-iteration nanoseconds × whole-process nanoseconds. Bootstrap 10,000 resamples of six paired-block log ratios with replacement. Deterministic SplitMix64 stream: base seed 10,000; per endpoint seed is `(10000 XOR size_bytes XOR metric_code) mod 2^64`, metric codes `0x494e4e4552` (inner) and `0x50524f43455353` (process). Each random draw selects `next_u64 mod 6`; each bootstrap statistic is `exp(mean(sampled log ratios))`. Sort 10,000 statistics and take order statistic index `ceil(0.95*(10000-1)) = 9500` as the one-sided 95% upper bound. Claim normal-path noninferiority only if all four upper bounds are <=1.05. Otherwise report the failed endpoint and investigate overhead; do not suppress the result.
