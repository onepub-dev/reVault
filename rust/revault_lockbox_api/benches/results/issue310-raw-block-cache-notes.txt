Issue #310: reject whole-frame reservation for lazy verified raw blocks
Base 3d0cc5d; production remains f4b1d91. The attached candidate patch is fully
reverted. Only benchmark FILES configurability and evidence are retained.

Prototype: packed raw frames optionally shared authenticated blocks through the
cached native index. Only single-block ranges used this cache; crossing/large
reads retained contiguous I/O. Misses verified exactly the block already touched
by an ordinary partial read. Hits copied into a zeroizing result and rechecked
live source identity, full physical extent, revision and terminal source state
before returning data. No content key was retained. Allocation/reference/manifest
checks stayed in place. Metadata-only caching remained available for small budgets.
The cache reserved each frame's maximum eventual block footprint up front, though
blocks were filled lazily. This reservation policy is the rejected design.

Stress pooled medians: production 2341.249 ms, prototype 8660.913 ms, 3.699x slower.
Median of four paired slowdown ratios is 3.677x. Native/ZIP medians rise from 1.474
to 5.562. All four pairs show a large regression. The experiment establishes the
workload regression; attribution specifically to metadata eviction is consistent
with the reservation design but was not separately profiled by cache counters.
Reject the prototype despite the small-archive gain. Production sources and
candidate tests are restored; the new benchmark setting remains for future gates.

Next candidate should account for actually cached blocks within the shared cache
and evict individual blocks, preserving hot metadata. Existing PageCache LRU and
weight accounting may support separate verified-block entries. Such a design
still needs exact descriptor/ordinal/revision and physical-extent guards, bounded
admission, zeroization, lifecycle tests and the same over-capacity stress gate.
It is not implemented by this checkpoint. Read parity, cold I/O, protected write
gates, signed recovery and migration/release requirements remain open. Native
stays opt-in. Current normal release zip_read path contains the rejected prototype;
rebuild before production timing. No push or publication.
