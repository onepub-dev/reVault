Issue #310: reuse file metadata for native frame extent validation
Base: 1aa29e5, 2026-09-22, Linux x86_64.

Native frame open and subsequent extent checks previously validated archive
identity and then separately fetched file length. On Unix, use the held-file
metadata already fetched by identity validation for both purposes. Both path
and handle metadata are still queried for every validation; post-read identity
checks are unchanged. Other platforms retain their existing identity check and
separate length query. External sources retain ensure_current followed by len,
including failure latching. No archive format, authentication, cache or padding
changes. Page metadata validation is unchanged.

Three sequential before/after pairs, 15 samples per row, taskset -c 2:
REVAULT_ZIP_READ_CASE=small REVAULT_ZIP_READ_MODE=plain
REVAULT_ZIP_READ_SAMPLES=15; all other filters unset.
512 files x 4096 bytes; fresh file handles, warm OS cache, exact byte verification.
Before /tmp/issue310-stat-before built from 1aa29e5; after compiled with this patch.
No builds or tests overlapped untraced timing runs. Full rows in companion CSV.
