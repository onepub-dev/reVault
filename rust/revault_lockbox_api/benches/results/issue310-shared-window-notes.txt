Issue 310: share complete decoded native file-handle windows

Baseline production: 7119ae8. Native layout remains experimental/opt-in.
NativeFileReader previously obtained a Vec copy from the verified decoded-frame
cache and wiped that full handle-local allocation when changing frames/dropping.
It now retains an Arc and validated slice bounds when the requested window is
the complete decoded frame. Packed slices retain bounded zeroizing owned copies,
so one tiny open file cannot keep a whole frame of neighbors alive after cache
eviction. Disabled cache admission still returns owned zeroizing windows.

The native view helper preserves the compression policy previously enforced by
read_file_chunk_range. Exact reference/allocation/slice checks are unchanged.
The handle keeps its storage borrow, full required extent and revision; its
existing source check runs before every window copy. No content key is cached.
Cache-hit into_vec's temporary-copy guard is replaced by this handle guard;
there is no successful read before validation. Dropping the last Arc uses the
existing full-capacity zeroizing CachedCompressionFrame destructor. Format,
cache limits, write behavior and default layout are unchanged.
