Remove the preliminary current_len call in read_native_block_chunk_view's
verified decoded-cache hit path. Its only two consumers still validate live
source identity/extent and write revision before returning bytes: into_vec after
copying into ZeroizingBytes, and extraction before invoking the writer. Invalid
copies are wiped. Exact committed reference, allocation, manifest membership,
range bounds, revision-tagged cache lookup and final revision checks remain.
Fresh reads and NativeFileReader's retained-window checks are unchanged.
No format, public API, cache policy, hashing, signing or encryption change.
If both cached metadata and the live source are invalid, metadata rejection can
now precede the live-source error; neither path exposes bytes.

Extend the existing all-protection/all-padding native truncation fault test:
assert one decoded cache entry remains, attempt extraction, and verify failure
leaves the destination empty. Existing overwrite, read handle, range and content
stream assertions remain. Direct backing-file fault injection is already
explicitly documented because no public CLI can create this fault.

Main protocol matches slice-order evidence: eight alternating-order rounds,
nine samples/row, 512 x 4096-byte files, plain mode, Interactive/BulkImport
creation, Interactive/ReadMostly reads, pattern/random input, requested raw/
compressed storage, public Read handles (ACCESS=random), PASSES=1,2. Each sample
opens a fresh archive; passes reuse its handle. 512 rows. Large controls: three
alternating rounds, five samples, four 8 MiB files, Interactive creation, both
corpora/read profiles/compression settings, PASSES=1; 48 rows. CPU 2, warm OS
caches. All returned bytes checked on every pass. No owned builds/tests overlap
timings; unrelated host activity was not controlled.

Small results: packed compressed pattern first reads improve 1.131x/1.144x
(Interactive/ReadMostly), and two passes improve 1.230x/1.221x. First-read ratios
to ZIP are 0.913/0.899: near a 10% lead for these particular warm compressed
cases, not evidence of broad issue completion. Separate small-file first reads
range 0.971-1.046x; all eight separate-file two-pass groups improve 1.043-1.170x.
Packed raw/incompressible controls remain mixed, 0.975-1.069x for first reads
and 0.978-1.022x for two passes. Their ZIP gap remains unresolved.

Initial large compressed pattern results slowed: 0.926x/0.897x. This triggered
a fixed eight-round follow-up with the same binaries, alternating order and
five samples/row; all eight large workload groups retained, 128 additional
rows. Follow-up compressed pattern results are 1.022x/1.054x; all groups range
0.996-1.054x. Thus the initial slowdown was not reproduced. Both datasets are
retained separately rather than replacing or selectively pooling observations.
These descriptive medians have no per-cell confidence intervals. Do not claim
a general large-file improvement or a statistical non-regression gate.
