Typed native integrity preparation, 2026-09-13
=============================================
Prepared frames now distinguish LegacyChecksum from NativeBlocksPending.
The native writer did not consume the pipeline's legacy whole-frame checksum;
it builds the committed block index instead. Native preparation no longer
performs that redundant full stored-data hash. Serial/batched and streaming
worker-job paths all select the same layout policy as their writer.

Legacy preparation is unchanged. Legacy writing rejects NativeBlocksPending
before changing storage, sequence numbers, statistics or chunk references. There
is no all-zero or other fake checksum. The native encoder still compresses once,
uses the prepared codec bytes unchanged, and creates all block/index protection.
No codec policy, native format or encryption change is introduced here.

Results do NOT establish a broad write no-regression gate:
- Pattern/raw/plain: paired estimate -10.418%, 95% interval [-21.906, -5.308].
- Random/compression-enabled/encrypted: -8.603%, interval [-16.923, -3.646].
- Random/raw/encrypted: +4.584%, interval [1.611, 64.179]; this concerning result
  must be rechecked, not dismissed merely because work was removed from code.
- Other intervals are wide and often cross zero; see both complete summaries.
Do not claim write parity or accept a >5% regression from these measurements.
Further isolated CPU/encoding measurement and more stable file-backed runs are
needed before native default activation, as are comparisons to the actual
default writer, load-time gates, all ZIP workloads, bindings and release checks.

Follow-up: issue310-native-write-integrity-focused-notes.txt records separate
25-group runs for raw/encrypted and compression-enabled/plain high-entropy data.
Their upper 95% bounds were +0.558% and +2.314%, respectively, below the +5%
threshold. The earlier concerning increases were not reproduced in those focused
