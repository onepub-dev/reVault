Two fixture assumptions were corrected without disabling their assertions:
- Packed-page relocation now scans and validates native page length, page ID,
  descriptor and sequence when applicable. Legacy page-size validation remains.
  Both branches independently reopen, compare survivor bytes, verify storage,
  and assert absence of all 79 deleted files. The focused test passes both with

- Multiframe corruption/recovery selects the subject's pages using committed

  the neighboring file; scanner position zero is not necessarily the subject.
  Total page counts and removal of exactly the damaged page remain asserted.

The second correction exposes a deeper existing failure, retained as a failing
assertion: encrypted=false, signed=true, compression=None, padding=Default.
After corrupting one subject data block, recovery reports TWO partial files,
not one. The intact neighboring native file loses authorization too.
RecoverySession::native_signed_snapshot invokes the full normal open, which
calls verify_signed_content and computes signed_content_digest over every
file. A damaged file prevents creation of the trusted snapshot for all native
entries. Simply bypassing that authentication would not be a valid fix.
The existing signed TOC-loss recovery failures need the same contract review:
establish how each recovered descriptor can retain owner authorization without
depending on unrelated readable content. Do not weaken owner-signature checks.
