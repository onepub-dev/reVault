Both optimized native-block-layout zip_read binaries use the same bench source.

Decoded native cache entries now retain the exact verified block reference and
physical segment by value. Their memory is included in the existing page-cache
budget. A hit validates the requested chunk, matches that reference and segment,
checks the requested manifest slice, and checks the current source extent and
write revision before returning cached bytes. Failed final checks wipe the output
copy. A miss still opens and verifies the full metadata/index normally; it does
not perform an additional current-length query solely for the cache fast path.

This is reuse of previously authenticated bytes, not trust in an index checksum
read from disk without a committed descriptor. File replacement, physical padding
truncation, own-backend overwrite revisions, external cancellation and terminal
failure checks remain enforced. Arbitrary same-size writes by uncooperative
external processes are not a new freshness guarantee. No format/API change.

Measurements: issue310-native-whole-cache-paired.csv, 96 rows. Within each of three
runs and four creation/corpus combinations, run saved before and after binaries;
reverse their order in the second run. Each invocation uses CASE=small, MODE=plain,
ACCESS=whole, SAMPLES=5, explicit CREATE_PROFILE and CORPUS, and leaves PROFILE and
COMPRESSION unset. Use the REVAULT_ZIP_READ_ prefix for all those environment names.
Build with cargo bench -p revault_lockbox_api --features native-block-layout
--bench zip_read --no-run. See the preceding whole-current notes for corpus and
sample semantics. Each phase byte-verifies 122880 file results (480 MiB) per
implementation. OS caches remain warm; each sample opens a fresh archive handle.

Medians of the three per-run medians:
- BulkImport packed creation: 77.124-101.357 ms before, 5.990-8.498 ms after;
  individual case speedups 10.83-16.92x. After/ZIP ratios 0.823-1.057.
- Interactive creation: case speedups 0.92-1.06x, after/ZIP 2.411-2.773.
  Mixed small changes do not establish non-regression on this shared host.
- Packed reads approach ZIP, but not every case meets parity or a 10%-faster
  threshold. Interactive-created archives still miss the issue target substantially.
  This is not broad performance parity, nor large/protected/cold-OS-cache evidence.
