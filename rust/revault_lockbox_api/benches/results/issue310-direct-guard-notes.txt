Issue 310: consolidate source validation for direct native raw reads

Base production: 50c7d29. Native layout remains experimental and opt-in.
Complete aligned plaintext raw blocks are read directly into the caller's
initialized output buffer and checked against the authenticated block index.
Previously this path checked full source extent/revision before I/O and source
identity again after hashing. It now checks full source extent, revision and
identity once after hashing and before returning success. Read/checksum/source
errors still wipe the complete caller buffer. External reads retain their own
terminal-failure checks. AEAD paths, ordinary owned reads, cached partial reads,
format bytes and write behavior are unchanged.

This is safe because the mutable caller buffer cannot be returned successfully
until both block verification and the final source check succeed. A valid hash
is insufficient when source authority changed. New tests keep all packet bytes
valid but remove only allocation padding, write identical bytes through a shared
storage clone (changing revision), or replace the archive path on Unix. Each
fault must fail and zero the whole output. Existing corruption, truncation,
external cancellation/version/short-read/failure-latching tests also pass.
