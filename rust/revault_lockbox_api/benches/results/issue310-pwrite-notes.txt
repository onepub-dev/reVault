Issue #310: Unix positional writes, base 4c2ba4b, 2026-09-22

FileStore::write_at now uses std::os::unix::fs::FileExt::write_all_at while holding
the existing exclusive in-process lock and checking archive path identity.
This removes the separate cursor seek for each write_at. Append still seeks to
the actual end under that same lock; it does not depend on a preceding write's
cursor. Non-Unix builds retain seek + write_all. Partial writes/retries use the
standard library's exact-write implementation. No durability sync, authentication,
preparation ordering or format change.

A focused storage test verifies cursor preservation, overwrite, append, a write
extending beyond EOF with a gap, another append, sync, and independent persisted
byte comparison. Existing concurrent cloned readers/writers, replacement refusal,
archive locking and native preparation/abort tests pass. Native public lifecycle
passes all sixteen protection/compression/padding combinations.
