Issue #310: combine adjacent native page/index source validation
Base 0be68ca, 2026-09-22.

The native metadata reader previously checked identity, read the header, fetched
length separately, decoded metadata, then checked identity again. The block index
opener immediately repeated identity+length validation before reading the index.

Metadata now obtains identity+length together at entry and after metadata decoding,
and validates the full padded page extent both times. Its private Metadata result
carries the final length to a private block-index opening helper. That helper still
validates the descriptor/packet extent, reads/authenticates the index and checks
source identity afterwards. No byte reads or user callbacks intervene between the
metadata check and index opening except index opening itself. Direct frame tests
retain a standalone opener which obtains its own current length first.

Frame reads and cache hits continue their independent identity/extent validation.
External storage retains ensure_current/len failure latching and read validation.
Metadata/header limits, checksums, AEAD and TOC/owner authorization are unchanged.
No archive format, public API or cache lifetime changes. Private validated length
is consumed only by the containing page reader/scanner, not reused across calls.
