The pinned zeroize 1.9.0 implementation clears [MaybeUninit<Z>] by casting to
MaybeUninit<u8> and performing volatile byte writes. The existing helper widened
initialized bytes but still used that byte loop for spare capacity. Large spare
allocations can remain after compression or partial-range reads.

Change: add transparent SpareWipeBlock(MaybeUninit<WipeBlock>) with an all-zero
Default and DefaultIsZeroes. It accepts uninitialized memory, unlike WipeBlock.
Align the exclusive spare slice into head, wide blocks and tail; use zeroize
on all three. Its DefaultIsZeroes slice path issues wide volatile stores.
No uninitialized byte is read or converted into an initialized integer value.
WipeBlock has no padding; the wrapper retains its size/alignment. The new unsafe
alignment operation has a local safety explanation. Existing zeroize writes and
optimization barriers remain; vector length/capacity and full-allocation wiping
are preserved. No key, format, authentication, allocation-size or cache-policy
change. This does not retain the rejected batching code.

New test covers genuinely uninitialized subranges at 32 offsets and lengths
0..129, checking zeroed selected bytes and intact neighboring bytes; it also
checks a never-initialized Vec capacity with zero logical length. Existing tests
cover initialized/truncated capacity and discarded native plaintext. Only bytes
initialized by setup or the wipe are inspected through assume_init. Miri is not
installed in this toolchain; no Miri run is claimed.
