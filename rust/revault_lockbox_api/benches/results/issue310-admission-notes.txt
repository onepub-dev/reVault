Issue #310: reject delayed large-frame cache admission; measure repeated reads

Production baseline: 4be2063. Production code was restored to that revision
after this experiment. The retained code change is benchmark PASSES support.
Before binary SHA256: a397b16a3a449b7f31b4c71ecaace6bbb8a6676e95534e7fe9e4cb39c6de5f53
Rejected prototype SHA256: c4d7b32dd99ab4f3bef21f6daeec0760048d9023351cac470b43735c6efc4dfd
Both binaries include identical new repeated-pass benchmark code, built release
with native-block-layout. No format, default activation or public API change.

The prototype delayed decoded-frame admission for standalone native frames
larger than BLOCK_BYTES (16 KiB) under Interactive/BulkImport until the existing
bounded NativeIndex cache entry had been reused (matching write revision and
cache-entry generation > 0). Small/packed frames and ReadMostly/ExtractMany
kept eager admission. No additional unbounded history or authentication bypass.
Focused native tests checked all protection modes, repeated reads, and disabled
cache; they passed apart from the pre-existing signed-neighbor recovery failure.
The prototype and its policy-specific test were removed after the measurements.

The new REVAULT_ZIP_READ_PASSES environment option defaults to one. It repeats
all requested reads on the same archive handle within a sample for both ZIP and
Lockbox, verifying every returned byte on every pass. Each timed sample still
opens a fresh archive. PASSES must be recorded alongside the CSV (the base
16-column CSV shape is unchanged), as done in this experiment's prefix columns.

admission-reads.csv: 192 rows; four alternating-order before/after runs,
five samples per row, four 8 MiB files, plain mode, Interactive creation,
pattern/random corpora, both requested compression settings and
Interactive/ReadMostly read profiles. ACCESS=whole. PASSES=1,2,5. OS caches
warm; no decoded Lockbox data survives across timed samples. Requested
compression=true on incompressible input falls back to raw native frames.
The ReadMostly rows are unchanged-policy controls.

Decision: reject the policy. Interactive first reads improve 1.66-2.07x,
but two-pass sequences take 15-35% longer and five-pass sequences 15-28%
longer. ReadMostly controls remain near parity between implementations.
A first-read-only benchmark would have concealed these realistic regressions.

Next work should reduce the copying/allocation cost of retaining decoded data
and assembling multi-frame output while preserving warm reuse, rather than
moving repeated hash/decode work onto the second read. Neither this experiment
nor the existing large-file measurements establishes ZIP parity. The two known
native recovery failures remain unresolved and native layout stays opt-in.

builds succeeded, and all 192 rows completed with byte verification on every
pass. Production behavior is unchanged from 4be2063 after the scoped restore.
