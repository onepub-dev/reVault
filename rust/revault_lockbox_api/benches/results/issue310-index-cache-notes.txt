After measurement, an equivalent allocation-reference comparison stopped
cloning its fixed-size struct; production declarations were moved ahead of
tests. These changes and the pre-commit formatting hook do not alter semantics.
Release zip_read benchmark, native-block-layout enabled, plain mode.
Feature remains unreleased/opt-in; no format or public API changes.

Native readers retain shared verified manifest and block-index allocations.
The existing bounded PageCache can retain metadata/index proofs separately
from decoded frames, charging their memory instead of physical page size.
Proofs match the exact committed reference and segment and revalidate the
live source identity, extent, write revision and external terminal state.
Each requested raw data block is still read and authenticated. No content key
or storage borrow is retained in the index cache. Disabled/undersized caches
refuse admission, dirty encoded pages remain intact, and decoded frames take
precedence over index-only entries at the same physical offset.

Small standalone raw frames that fit within one logical block and one bounded
physical allocation use the existing whole-frame snapshot path. This avoids
metadata/index admission overhead for separate small files without reading
additional raw blocks. The initial index-only prototype regressed those cases;
the committed CSV measures the subsequent bounded-snapshot adjustment.

96 CSV rows: three interleaved before/after runs, five samples per row,
512 x 4096-byte files, Interactive/BulkImport creation, pattern/random corpora,
both compression settings and Interactive/ReadMostly read profiles.
ACCESS=random means shuffled public Read handles. Each phase checks 480 MiB
of returned file bytes across fresh archive handles; OS caches are warm.
The compressed column is requested policy: incompressible data uses raw
fallback and therefore exercises the raw index/snapshot paths.

Packed raw/fallback handles improve 5.1-6.4x but still take 2.1-2.34x ZIP.
Standalone raw/fallback handles improve 1.6-1.9x, still taking 1.19-1.34x ZIP.
Compressed handle controls show mixed small differences (0.97-1.09x speedup).
This matrix does not establish broad parity or cold-storage performance;
large-file and signed/encrypted timing, write lifecycles and recovery gates
remain outstanding. The feature must not be activated based on these results.

Regressions added/extended:
- A new raw neighboring handle fetches exactly one data block after the first
  handle, with no repeated metadata/index source reads, in all protection modes.
- Warm index proofs reject 14 mutations of references/descriptors/allocations.
- Every workload profile enforces disabled, undersized and bounded index-cache
  budgets and eviction while partial raw handles retain no decoded frames.
- Small cold Read handles verify bytes using one source read and reject
  cancellation, corrupted metadata and truncated allocation padding.
- Existing cloned-backend overwrite, truncation and sticky failure tests remain.
